# 设计特点

这篇讲 Content Cook 的设计原则，以及每个模块最关键的设计：用户看到的是什么样子，为什么这样设计。
每一条都能在代码里找到对应实现，文中给出主要位置，方便核对。

- 设计的完整记录（每次改动的来龙去脉、验收、未验证项）在 [DESIGN.md](../../DESIGN.md)（中文长文），本文按主题摘要，并链接到对应章节。
- 代码分层与数据流见 [架构](architecture.md)；角色、来源、环境变量见 [配置](configuration.md)；安装与打包见 [安装与部署](installation.md)。

> **关于命名**：产品名「Content Cook · 内容创作工作台」是工作名，只在 `src/webui/branding.py` 一处定义。
> Python 包名 `storystudio`、命令行 `storystudio` / `storyvideo`、设置目录 `~/.storystudio`、桌面程序 StoryStudio（Windows 上是 `StoryStudio.exe`，macOS 打包脚本产出 `StoryStudio.app`）都是技术标识，有意不跟着产品名改。

## 一、设计原则

| # | 原则 | 用户看到的 | 主要代码 |
|---|---|---|---|
| 1 | 本地优先 | 服务只在本机，项目、产物、账本、密钥都在自己电脑上 | `src/studio/desktop.py`、`src/genkit/paths.py` |
| 2 | 自带模型，按角色配 | 文本 / 生图 / 语音 / 视频 / 配乐五个角色，各选一个来源 | `src/genkit/settings.py`、`src/genkit/adapters/` |
| 3 | 花钱透明 | 先预估、再确认、才生成；没确认不花钱 | `src/webui/generate.py`、`src/webui/routers/episodes.py` |
| 4 | 产物从不覆盖 | 每次生成都写新文件，旧的留着 | `src/clip/generate.py`、`src/imageset/generate.py`、`src/music/generate.py`、`src/picturebook/pages.py` |
| 5 | 冻结与版本 | 开始制作后，改会进提示词的内容要开新版本 | `src/genkit/store.py`、`src/webui/revise.py` |
| 6 | 阶段之间有审片闸 | 首帧过了才出视频，全部过了才装配 | `src/storyvideo/qc.py`、`src/storyvideo/asr_qc.py` |
| 7 | 检查要说清怎么改 | 问题卡写「影响——改法」；模型审稿的引文由程序核对 | `src/webui/problems.py`、`src/storyvideo/genre_review.py` |
| 8 | 提示词由结构化数据编译 | 按目标模型换写法（方言），改动由金丝雀把关 | `src/storyvideo/prompts.py`、`scripts/refresh_prompt_canary.py` |
| 9 | 缺件时照常可用 | 缺模型、插件、ffmpeg 时说清缺什么，应用不崩 | `src/webui/deps.py`、`src/genkit/plugins.py` |
| 10 | 中英双语 | 界面、后端提示、提示词语言都支持中英 | `frontend/src/i18n.js`、`src/webui/i18n.py` |
| 11 | 默认安全 | 本机令牌、Host / Origin 校验、密钥打码 | `src/webui/app.py`、`src/genkit/logmask.py` |

### 1. 本地优先：数据留在本机

- 服务只绑 `127.0.0.1`（`src/studio/desktop.py`），不支持局域网或远程访问。
- 项目文件、产物和账本放在**数据目录**：开发态默认是当前目录，桌面版默认 `~/StoryStudio`，可以用 `--project-root` 或环境变量 `STORYSTUDIO_PROJECT_ROOT` 指定。
- 设置、密钥、日志、音色库默认放在 `~/.storystudio`（环境变量 `STORYSTUDIO_HOME` 可改）。各目录的完整布局见 [配置](configuration.md)。
- 会离开本机的内容：
  - 生成时的提示词、参考图 / 参考音频和参数，发给**你自己配置的**模型来源。
  - 绘本朗读、播客配音没选音色时用 Edge TTS（微软的在线朗读服务）占位；短剧旁白没指定引擎时，「模型设置」里配了非 Edge 的语音来源就用它，否则用 Edge TTS；音色库里引擎为 `edge` 的音色也走 Edge TTS。要念的文字会发给相应的服务。
  - 音色克隆会把你上传的参考录音发给 MiniMax。
- 下面这些联网由你的操作触发：
  - 刷新 OpenRouter 公开模型目录；
  - 检查更新（填了更新地址才查，只查不下载）；
  - 打开音色库页面时拉一次 Edge TTS 在线音色列表（切换引擎或语言时会再拉）；
  - 一键安装台词识别（从 PyPI）；
  - 下载台词识别模型（从 Hugging Face；可以在设置页预下载，没下载过的话第一次跑台词识别时也会下载）；
  - 打开旧版页面（短剧项目「高级」页里有它的链接）时，它会从 Google Fonts 加载网页字体（新界面不加载外部字体）。
- 代码里没有遥测，也不上报使用数据。

**为什么**：剧本、人物照片、声音这些素材往往是私人的。这个工具给一个人或一个小团队在一台电脑上用，不需要服务器。
详见 [DESIGN.md §3 产品原则](../../DESIGN.md#3-产品原则)。

### 2. 自带模型，按角色配

- 模型按**角色**配置，不按厂商：文本（剧本、起草、审稿）、生图、语音、视频、配乐。每个角色选一个来源（适配器），填地址、密钥、模型。
- 来源有四条路，可以混用：
  - 各家直连：OpenAI 兼容接口、OpenRouter、火山方舟、MiniMax、Edge TTS。
  - 统一网关：LiteLLM、new-api、one-api 这类 OpenAI 兼容网关，在设置页填一次地址和密钥，一键应用到文本 / 生图 / 语音 / 视频四个角色（配乐没有通用的接口形状，不在其中）。
  - 本机模型：「扫描本机」能找到在跑的 Ollama、LM Studio、vLLM、llama.cpp、ComfyUI、SD WebUI 和本机语音接口。
    本机地址不需要密钥，也不花钱。这是可选的路，不配本机模型，云端来源照常可用。
  - 插件：内置来源之外的来源写成插件，放在仓库之外（见 [docs/plugins.md](../plugins.md)）。
- 流水线只认角色：项目里写 `"@image"` / `"@video"` 表示「用模型设置里那个模型」；写具体模型 id 则以项目为准。
- 能力表（`src/genkit/capabilities.py`）记录各模型能接受的时长、分辨率、画幅。开始制作前先检查一遍，分辨率会自动对齐到模型支持的最近档位。
- 有官方 SDK 就用 SDK（OpenAI、OpenRouter、火山方舟）；只有没 SDK 的接口才手写 HTTP（MiniMax、SD WebUI、ComfyUI，以及 OpenAI Videos 形状的视频接口）。

**为什么**：模型换得很快，每个人手上的账号也不一样。换模型不该重写项目，新增一个来源也不该改流水线。
详见 [DESIGN.md §14 统一网关](../../DESIGN.md#14-统一网关2026-09-07)、[§45 本地模型](../../DESIGN.md#45-本地模型2026-09-10)、[§57 插件来源](../../DESIGN.md#57-插件来源2026-09-23)。

### 3. 花钱透明：预估 → 确认 → 生成

- **短剧**的生成分两步：
  1. 预估（`GET …/generate-estimate`，只读、不花钱）：列出这一批要新提交哪些镜、用什么模型，哪些已经有了、哪些还在生成、哪些失败了，并返回一个 `plan_token`（按项目、阶段、待提交的镜和模型算出的哈希）。
  2. 生成（`POST …/generate`）：必须带上同一个 `plan_token`。服务端当场重算一遍，对不上（你看过预估之后磁盘状态变了）就返回 409，什么都不提交。提交前还会检查需要的角色配好没有，没配就 400，不锁草稿。
- **其他模块**：生成前的确认框写明要发几次请求，例如「出一张首帧？会发 1 次生图请求（花钱）。」
- **本机来源**：确认框写「本地生成，不花钱（N 次请求）」。读不出设置时宁可按「会花钱」提示，也不把付费来源说成免费。
- 程序只数请求次数，不知道各家价格，所以不显示金额估算。
- 起草和审稿每点一次只发起一次生成：程序不自动重试，也不「多生成几个挑最好的」。
  （文本来源是 OpenAI 兼容接口时，底层 OpenAI SDK 遇到连接失败、限流或服务端 5xx 最多自己再试 1 次；网关不认流式参数时，会去掉这些参数重发。）
- 花钱的只有调用模型的那几步。静态检查、提示词预览、装配、台词识别、图片后处理、打包、复制示例都在本机完成，不花钱。
- 后期合成本身在本机跑，但旁白和台词配音要先用 TTS 合成：用到的语音来源是付费的（「模型设置」里的付费语音来源，或音色库里选了 MiniMax 的音色）时，这一步会调用它；用 Edge TTS 或本机语音接口时不花钱。

**为什么**：`plan_token` 防的不是恶意调用，而是一次意外的重复点击或重复请求，在人还没看清「这次要提交几个」之前就把钱花出去。
真正的防重复提交由账本的状态机负责（见第 5 条）。

### 4. 产物从不覆盖：每次都留着，挑一版

每次生成都写一个新文件，挑一版不会删掉别的版本。
单条视频、图片集、绘本、配乐、剧本工作台用 `current` 指针表示采用了哪一次；短剧重拍时把旧文件留底到 `takes/`（目前界面上不能改选回留底的旧版），海报以最新一张为当前。

| 模块 | 新产物落在哪里 |
|---|---|
| 短剧 | 重拍前，旧的首帧 / 视频留底到 `01_frames/takes/<镜>/`、`02_video/takes/<镜>/` |
| 单条视频 | `01_video/<ID>-<n>.mp4`，项目文件里记 `attempts[]` 和 `current` |
| 图片集（表情与头像、纪念写真、图片工作台） | `01_raw/<图>-<n>.png`；后处理结果在 `05_out/`，文件名带运行戳 |
| 绘本 | `05_pages/P01-<n>.png` |
| 配乐 | `01_raw/<ID>-<n>.<扩展名>` |
| 海报 | `07_poster/base-<毫秒>.png`、`poster-<毫秒>.png` |
| 剧本工作台 | 每次生成、局部重写、手改、导入都是新的一版 |

- 失败也记一条（带原因），不会替换上一次好的结果。
- 成片、混音这类成品先写临时文件，再原子替换。
- 请求哈希（提示词、模型、参数、参考图内容）没变、文件也还在，就跳过不重出；想重出要显式「强制」。

**为什么**：生成式模型每次结果都不一样，「上一次其实更好」很常见。花钱换来的东西，不该被下一次覆盖掉。

### 5. 冻结与版本：开始制作后改动要留痕

这一条针对短剧。

- 点「开始制作」（命令行是 `storyvideo prepare`）后，项目被冻结成 `<项目输出目录>/manifests/episode.snapshot.json`，同时建立账本（SQLite，`<数据目录>/output/story_video/storyvideo.sqlite3`）并编译提示词。
- 账本里每个任务都记下请求指纹 `request_hash`。调用服务商**之前**先写一条「正在提交」的记录：进程中途崩溃时，留下的是一条「提交结果不明」的记录等人核对，绝不会悄悄再交一次。
- 同一个版本里，输入或计划变了就拒绝（`already has different inputs`）；同一个任务的请求变了也拒绝（`already has different request metadata`）。
- 开始制作后，要改会进提示词或生成参数的内容（角色、画面、台词、模型……），就要开新版本。界面上只有一个动作「保存并预告费用」：
  - 逐镜比较编译后的首帧请求和视频请求，算出哪些镜要重出、哪些能复用。参考链会传染：被参考的镜首帧变了，引用它的镜也要重出。
  - 确认后复制成新版本，把能复用的产物和它们的审片结论带过去，只重新生成受影响的镜。旧版本一个字不动。
- 只改「后期块」（旁白、插卡、画面文字、字幕样式、标题等）不改变请求指纹，制作中直接生效。
- 同一份提示词原样重拍到第 3 次会被拦下（409，可以强制）：提示你改文字、换模型对比，或者接受当前结果。
- 已知限制：内置来源都不支持查询任务历史，「提交结果不明」的任务目前不能在原项目里解开，只能到服务商控制台核对后开新版本（见 [BACKLOG.md](../../BACKLOG.md) 的「已知问题」和 [STORYVIDEO_RUNTIME.md](../../STORYVIDEO_RUNTIME.md) §6）。

**为什么**：每一笔付费请求都要能追溯到它的输入。同时也防止改了一个字，就把整集悄悄重出一遍。
详见 [DESIGN.md §5.1](../../DESIGN.md#51-一集的生命周期)、[§11.2](../../DESIGN.md#112-三步落地)、[§24 重拍处置与重投纪律](../../DESIGN.md#24-重拍处置与重投纪律2026-09-08融合-drama-skills)。

### 6. 阶段之间有审片闸

- 短剧有三道人工审片闸：首帧、视频、成片。结论可以是 `pass` / `retake` / `edit_rescue` / `redesign` / `waive`。
- 顺序是硬性的：首帧没通过不出视频，所有闸都通过才装配成片。
- 人工审之前，程序先做技术检查（分辨率、文件是否有效、时长、音视频流）。
- 台词识别闸（可选，用本机 faster-whisper，不花钱）：把视频里的语音识别出来和台词比对。
  - 字错率 ≤ 0.3（默认值，命令行 `--threshold` 可改）算通过，≤ 0.45 待人耳复核，更高判为不通过。
  - 项目在制作中时，界面会给不通过的镜自动记一次重拍；命令行要加 `--record-retakes`。
  - 没有台词的镜，识别报告里会标出多出来的人声；命令行加 `--include-stray` 才把它算作不通过，界面上不算。
- 重拍时记下看到了什么缺陷（身份漂移、接缝断裂、台词错、文字残留、动作不对、审核拦截、画质等）和打算怎么处理（保留 / 后期处理 / 改文字重出 / 原样重提 / 换模型对比）。「保留」记为通过，「后期处理」记为豁免：接受，但不假装它通过了。

**为什么**：质检前置。先看首帧再花更贵的视频钱，先听台词再装配。「拼接顿挫、台词听不清、镜头接不上」这类问题要在成片之前发现。
详见 [DESIGN.md §5.3 质检](../../DESIGN.md#53-质检)。

### 7. 检查要说清怎么改，不只说有问题

- **静态检查**：短剧、AI 播客、剧本工作台、单条视频、绘本都有，在本机跑，不花钱。每条告警的格式是「位置: 影响——改法」，界面上变成问题卡（在哪、影响什么、怎么改），按类别上色、可以过滤。
  图片集（表情与头像、纪念写真、图片工作台）和配乐目前没有问题卡式的检查，只有保存时的校验；配乐会在提交前拦下没写意图的简报。
- **失败原因分类**：生成失败按原因分成六类：模型没配置、被服务商限流、余额或配额不足、内容被审核拦截、网络超时或服务不可用、服务商报错，每类配一句「怎么办」。
  被审核拦截的默认不原样重提，因为大概率还会被拦。
- **模型审稿**（各发 1 次文本模型请求）：短剧的按题材审稿和剧本工艺审稿、播客的真人感审稿、剧本工作台的审稿。
  - 模型必须逐字引用原文，并标出镜号或场号。
  - 程序逐字核对引文：对不上的条目降级，不进告警。
  - 正文改过之后，这份审稿标为「过时」。
- 检查里的阈值（字数、比例、秒数）是可以调整的经验值，不是行业标准；审稿清单写明了每条的依据和置信度。

**为什么**：只说「有问题」的检查没人愿意用。模型审稿可能编造问题，所以引文要由程序核对。
详见 [DESIGN.md §11.4 失败的任务](../../DESIGN.md#114-失败的任务2026-09-07)、[§49 按题材审稿](../../DESIGN.md#49-按题材审稿2026-09-11)。

### 8. 提示词由结构化数据编译

- 项目里存的是结构化字段（风格骨架、场景锚、角色、镜头、动作、台词、运镜、音效、连续性锁……），由编译器按固定顺序拼成提示词。
  镜头库和风格库是编译器的数据，可以在「镜头库与风格库」页逐条编辑，写盘前会校验。
- **方言**：同一份镜头事实，按目标模型的写法重新排列。
  - 视频（短剧）：`generic`（不写时的默认）、`minimax-h3`、`seedance`；选 `auto` 时按视频模型自动选。
  - 出图：`generic`、`gpt_image`、`nano_banana`；不指定（或选「自动」）时按出图模型 id 猜，猜不到用 `generic`。
  - 单条视频：`generic`、`nano_banana`。
- **默认不让模型画字**：出图类提示词（图片集、绘本插画、海报底图、短剧首帧）默认以「画面中绝对不出现任何文字、字母、数字或符号」收尾。
  要显示的字（海报标题、表情包短语、写真的祝语和日期、图卡标题）都在本机用 Pillow 叠加。
  例外是你明确要的画面文字：短剧某一镜确实需要能读的字（手机屏、招牌）时，在这一镜的 `readable_text` 里声明，首帧提示词改成「画面里唯一允许出现的文字：…」，静态检查会提醒文字过长；单条视频按你在【全片设定】里写的文字政策来。
- **金丝雀**：`scripts/refresh_prompt_canary.py` 把一份固定的迷你项目（外加每张形态卡 × 中英）编译一遍，和黄金输出比对。
  改编译器或库导致提示词变了，它就报漂移；确认是有意改动后才用 `--update` 接受。
- 新加的字段遵守「不写就零变化」：不用新字段的老项目，提示词不会因为加了字段而改变，有快照测试盯着。
  有意的措辞调整会在 CHANGELOG 里单独列出（例如 2026-09-23 的「提示词措辞调整」），这类调整会改变已有项目的请求指纹；已经开始制作的短剧升级后要开新版本。

**为什么**：冻结的账本靠请求指纹，提示词里任何一个字变了，所有项目的请求都会跟着变。所以编译结果必须可重复，改动必须是有意的。换模型只换写法，内容以项目为准。
详见 [DESIGN.md §5.2](../../DESIGN.md#52-一镜的提示词从哪来)、[§17 视频提示词方言](../../DESIGN.md#17-视频提示词方言2026-09-08融合-zenstory-drama-skills)、[§41 出图风格卡与图像方言](../../DESIGN.md#41-出图风格卡与图像方言2026-09-09)。

> 注意：「镜头库与风格库」页改的是程序自带的库文件。源码安装时它在仓库的 `skills/` 下；打包版在安装目录里，重装会被替换。

### 9. 缺件时照常可用

| 缺了什么 | 会怎样 |
|---|---|
| 某个角色没配模型 | 起任务**之前**就返回 400，说清去「模型设置」配哪个角色；不起任务、不锁草稿 |
| 配乐角色没有来源 | 说明内置来源不覆盖配乐，需要装一个提供它的插件；各模块上传本地音频做配乐不受影响 |
| 插件不在或加载失败 | 应用照常启动；设置页把指向它的角色标成「未加载」并写明原因，健康检查也能看到；在飞的任务继续等待、不记失败；保存设置不会悄悄清掉这个角色 |
| `ffmpeg` / `ffprobe` 不在 PATH | 界面顶部常驻提示并给下载链接；需要它的步骤会点名缺什么；播客的逐句音频照样出，只有混音那步说明原因 |
| 中文字体缺失 | 健康检查报告字体状态；图片集里叠字失败的那一张记为失败，其余照出 |
| faster-whisper 没装 | 台词识别闸说明怎么装，其他功能不受影响 |
| pywebview 没装 | 自动改用系统浏览器 |
| 用 `--port` 指定的端口被占 | 立刻退出，给出可以换的空闲端口；在 Windows 上还会说出是哪个程序占着（不指定端口时从 8756 起自动找空闲端口） |
| 设置文件损坏 | 下次保存时把坏文件改名成 `settings.json.broken-<时间戳>` 留作备份 |

**为什么**：缺一个组件，不该让整个应用打不开，更不该把项目卡在半路。

### 10. 中英双语

- 界面以中文为源文案，英文是翻译层；缺翻译时回落到中文，界面上不会出现空白或翻译 key。
- 语言选择存在浏览器的 `localStorage`（`storystudio_lang`），第一次按浏览器语言选，侧栏底部可以切换。
- 后端的提示和报错也跟着界面语言走：前端每个请求带 `X-StoryStudio-Lang`（没有时看 `Accept-Language`），中间件把 JSON 响应里的提示文字翻成英文；用户自己写的内容不翻。
- 内容本身也支持双语：提示词语言可选中文或英文；绘本默认出中英双语字幕；关系场景和播客的检查对英文稿使用英文词表。
- 不翻译的：编译出的提示词、库的内容、示例、日志。

**为什么**：源文案只有一份，就不会出现两套 key 互相对不上的问题。详见 [DESIGN.md §13 界面语言](../../DESIGN.md#13-界面语言2026-09-07)。

### 11. 默认安全

- 服务只绑 `127.0.0.1`。
- 通过启动器（`storystudio` 或 `python -m studio.desktop`）启动时，每次生成一个随机令牌。窗口用 `/?token=…` 打开，并设置 `HttpOnly`、`SameSite=Strict` 的 cookie；之后 `/api/*` 请求必须带这个 cookie 或 `X-StoryStudio-Token` 头，否则返回 401。
  用 `--no-token` 启动时不生成令牌（只建议调试接口时用，启动时会醒目提示）；下面的 Host 检查和跨站请求检查照样生效，只是 `Origin` 放宽到任何本机地址。
- `Host` 不是回环地址的请求一律 403（防 DNS rebinding）；浏览器标记为其他网站发起、或 `Origin` 不对的接口请求也是 403。
- 打包版不提供 `/docs`、`/openapi.json`。
- 密钥处理：
  - 接口回传的密钥一律打码。
  - 换来源会清空密钥；把地址改到另一个站点而没填新密钥，旧密钥也会清空，避免把它发给新地址。
  - 日志和任务记录会遮掉密钥、`Bearer` 令牌、URL 里的 `key=` 等参数。
- 「扫描本机」只连本机和内网地址，看起来像本机的公网地址（比如 `127.0.0.1.evil.com`）在发请求前就被拒绝，不会变成网络扫描器。
- 插件只从 `~/.storystudio/plugins/` 和 `STORYSTUDIO_PLUGIN_PATH` 加载，不从设置文件、数据目录、程序目录加载。
  这样一个网页或一个别人发来的项目包，没法借此在你电脑上执行代码。插件以你的用户权限运行，只装你信任的插件。
- 项目里写的路径被限制在数据目录之内；删除和恢复也不会把文件搬到数据目录之外。
- 发布前做过两轮自查：2026-09-22 的发布审计（87 条发现，86 条确认并修复，见 [release-audit](../release-audit-2026-09-22.md)），2026-09-23 的安全自查（19 条发现全部修复并补了回归测试，见 [security-review](../security-review-2026-09-23.md)）。

**为什么**：这个本机端口能花钱。同一台电脑上的其他程序或网页，不该能调用它。报告安全问题的方式见 [SECURITY.md](../../SECURITY.md)。

### 2.1 短剧

流程：剧本（按场）→ 拆镜 → 开始制作 → 首帧 → 视频 → 审片 → 装配成片 → 后期合成 → 海报与交付包。
命令行 `storyvideo` 和界面共用同一套运行时，命令说明见 [STORYVIDEO_RUNTIME.md](../../STORYVIDEO_RUNTIME.md)。

- **先有剧本再拆镜**：可以两步起草，先出只讲故事的按场剧本，在逐场编辑器里改好，再按剧本拆镜。
  从项目页拆镜会建一个新项目，已有的镜头（可能已经花过钱）不会被覆盖。
- **单集契约和系列交接**：开场钩子、集尾、本集必须兑现的事、留给下一集的事实。契约不进提示词，由静态检查核对正文有没有做到。
  系列记忆原样保留角色描述，起草下一集时防止角色漂移。
- **逐镜卡片和参考链**：一镜可以参考另一镜的首帧，首帧按依赖顺序一波一波地生成。链头错了整条链都错，所以长链建议先看前两张再放行。
- **开始制作前的能力检查**：时长、分辨率、画幅超出模型能力时，在花钱之前就拦下来（可以强制开始）。
- **冻结、账本、版本、审片闸**：见上面的原则 5 和 6。
- **后期层**：旁白（可以逐句换声线、按真实 TTS 时长出字幕）、台词配音（TTS 兜底）、配乐、整屏插卡、画面文字、角标、静音、字幕样式。
  这些都是后期块，制作中也能改，不动生成请求。
- **分段流式合成**：后期合成按段处理再拼接，普通内存的电脑也能出长片（以前把全片塞进一条 ffmpeg 命令，内存随镜数暴涨，见 [CHANGELOG](../../CHANGELOG.md)）。
- **海报**：底图用生图模型出，或者直接拿某一镜的首帧（不花钱）；标题在本机叠加。
- **交付包**：只按白名单拷贝，附 `manifest.json`、`checksums.sha256` 和 `ai_disclosure.md`（AI 生成说明与工具清单，首帧和视频按账本记录的来源与模型列出）。
  设置、密钥、账本和上传的素材都不会进包。
- **后台轮询**：提交后由服务端每 15 秒问一次服务商，最多等 60 分钟，同一个错误连续出现 3 次才停。
  这个过程只轮询、下载、记账，从不提交；服务重启后自动接着等。

**为什么**：把一集拆成可以逐镜审、逐镜重拍的单位，花钱之前和之后都能看清每一步。
详见 [DESIGN.md §5](../../DESIGN.md#5-核心流程)、[§11](../../DESIGN.md#11-以资源为中心的工作台重构计划2026-09-07-立项)、[§32](../../DESIGN.md#32-剧本层单集契约与系列交接2026-09-08融合-drama-skills)。
后台轮询见 [§34](../../DESIGN.md#34-后台轮询与断点续等2026-09-08)，海报见 [§36](../../DESIGN.md#36-海报2026-09-08)，后期层见 [§56](../../DESIGN.md#56-长片需要的后期层与大首帧上传2026-09-22)。
短剧的部分判据参考了 MIT 许可的 drama-skills 项目，出处见 [第三方声明](../third-party-notices.md)。

### 2.2 AI 播客

- **一期的形状**：环节（冷开场、开场、话题、听友问答、收尾）+ 1–4 位主播。形式有单人、双人对谈、访谈、圆桌，决定人数和角色约束。
  说话人写错会直接拒绝保存，不会悄悄丢句子。
- **「像真人播客」落在三处**：
  1. 起草提示词里的八条约束：口语不是书面语、要有人不同意、具体压倒观点（素材只从简报里取，不许编数据）、每个人有自己的立场、问答要像回答、冷开场不自我介绍、禁止排比和「今天聊了三点」这类套路、时长可以数出来。
  2. 静态检查用同一套判据反过来查稿子：书面语、独白过长、机械轮流、一人独大、全程没分歧、填充词过多或完全没有、话题没有具体例子、回答太短或在复述问题、时长偏离目标等。
  3. 混音时的停顿：句间 0.35 秒、环节间 1.2 秒，标了「停顿」的句子再加 0.6 秒；片头曲放在冷开场之后。
- **只重写一个环节**：其余环节原文作为上下文，不会被改动。
- **真人感审稿**：一份 11 条的清单，模型逐条判断，程序核对引文。
- **配音和混音**：逐句 TTS，文本和音色参数没变就跳过；混音做响度标准化（-16 LUFS）；句子超过 64 句先分组预混，避免超出 Windows 命令行长度上限。
- **交付包**：成品音频、节目单、逐字稿、章节、逐句音频和 AI 生成说明。

**为什么**：AI 直出的对谈稿常常像书面文章。把「像真人」拆成能执行、能检查的规则，改稿才有方向。
这是目前唯一用真实文本模型（经 OpenAI 兼容接口）加 edge-tts 从头到尾走通过的模块。
详见 [DESIGN.md §50](../../DESIGN.md#50-ai-播客模块2026-09-16)、[§54](../../DESIGN.md#54-用真实文本模型走通播客全流程2026-09-18)。

### 2.3 剧本工作台

- **写 → 试 → 比 → 挑 → 用**：每次生成、局部重写、手改、导入都存成新的一版，`current` 指向采用的那一版。
  生成完不会自动采用，要人比过再挑；只有第一版例外，因为没有可以比的对象。
- **段落骨架由人来写**（种类、标题、目标），每一版只存每段的台词。段号对得上，两版才能逐段并排比较。
- **不新造判据**：检查和审稿借用播客和短剧已有的规则。按汉字定的阈值（比如单句字数）只用来判中文稿，不硬套到英文稿上。
- **投放和导入都是拷贝**：把采用的那一版写进播客环节、短剧剧本的场次或某一镜，写回时一律走目标模块自己的校验。
  已经开始制作的短剧不能往镜头里写台词（台词会进提示词）；这一版里没写台词的段不投放，不会把目标那边原有的台词清空。

**为什么**：台词是播客和短剧最弱的一环。需要一个地方能「同一段换三种写法再挑一版」，改坏了也能退回去。
详见 [DESIGN.md §55](../../DESIGN.md#55-剧本工作台2026-09-20)。

### 2.4 单条视频

- **一个项目就是一条片子**：不拆镜、不进账本。
- **三段式提示词**：【全片设定】（画风、色板、光线、画幅、安全区、文字政策、声音）、【分段时间线】（按绝对时间一拍一行）、【衔接与收尾】（一镜到底或转场、最后一帧、禁止事项）。画幅在同一句里写明，并排除另一种画幅，只出现一次，避免前后矛盾。
- **时间轴对不上只是告警**：空洞、重叠、总时长不一致都是告警，不是错误，写到一半的项目也能打开。
- **首帧三种方式**：不用首帧（文生视频）、上传一张、先生成一张（多花 1 次生图请求）。
- **从不覆盖、可以续等**：异步来源一条最多等 45 分钟；服务重启后会接着等没回来的那条，只轮询不提交。

**为什么**：一条 15–30 秒、一次生成到底的视频，需要的是另一种写法；短剧那套逐镜产线在这里太重。
详见 [DESIGN.md §43](../../DESIGN.md#43-单条视频模块2026-09-10) 和 [prompt-patterns](../prompt-patterns.md)。

### 2.5 绘本 / 有声书

- **每页时长由朗读决定**：一页的时长等于这一页朗读音频的实际长度（用 ffprobe 量出），加上进页、两种语言之间、出页的停顿。2–4 岁档停得更久；封面和封底多留几秒。
  没有音频时按字数估一个，只用于预览，装配前必须有真实音频。
- **插画提示词顺序固定**：风格锚（每页逐字相同）→ 场景锚 → 出场角色 → 画面 → 构图（下三分之一留给字幕）→ 排他句（画面里只有这几个角色）→ 不画文字。
- **按年龄段检查**（2–4 / 4–6 / 6–8 岁）：每页中文字数和全书页数按年龄段设范围，年龄越小越严（2–4 岁每页不超过 20 字、全书 8–10 页；4–6 岁每页 20–40 字、10–14 页；6–8 岁每页 40–70 字、12–16 页）。
  还会检查翻页钩、拟声词、一页一个动作、结尾是否安稳等。起草时要求英文像英语母语的童书那样写，不逐字对照中文。
- **出片**：默认中英双语（逐句交替；也可以整页先中文后英文，或只出中文、只出英文）；双语时中文字幕在上、英文在下，正在念的那句高亮；全书响度归一到 -14 LUFS；竖版 9:16 为主，可加出横版 16:9。
  按页出片段再流复制拼接，内存不随页数增长。
- **不建账本**：每本书的状态就是三份清单（插画、朗读、时间轴）。插画同样从不覆盖。
- **音色**：没选音色时用 edge-tts 占位出片，并标明「占位」；正式音色从音色库选。也可以导出朗读稿（xlsx）交给真人配音，再把音频收回来。

**为什么**：有声绘本的节奏由朗读决定，而不是先定好页时长再让朗读去凑。
详见 [DESIGN.md §39](../../DESIGN.md#39-绘本--有声书模块2026-09-09)。

### 2.6 图片集引擎：表情与头像、纪念写真

- **一个引擎加模板包**：按模板展开一组图（展开不调模型、不花钱）→ 逐张出图 → 挑选 → 本机后处理 → 打包 zip。
- **七个模板**：表情包、贴图、头像；满月、百天、周岁、婚纱。模板带一份表单描述，前端直接按它渲染，加一个模板只需要加一条注册。
- **文字不让模型画**：表情包的短语、百天的「100」、写真的祝语和日期，都在本机叠加。
- **安全约束不是可选项**：
  - 婴儿的三个模板每张都带固定的安全描述（口鼻周围干净无遮挡、脸上没有饰品、脸周只有柔软织物），蛋糕场景写明没有火焰。
  - 真人写真要求保持原本的脸型和五官比例、肤色自然，负面词拦住过度美白和过度磨皮。
  - 婚纱是唯一逐人点名的模板：参考图标了新娘 / 新郎，就逐人点名，并写明画面里只有这些人；其余写真带单人锁（「画面里只有这一个人」）。
    已知不一致：百天和周岁模板里的「全家福」场景要画父母和宝宝三个人，目前同样带着单人锁。
- **后处理在本机**：白底转透明用从边缘开始的泛洪填充（不引入抠图模型）；按规格出尺寸，例如微信表情主图 240×240、PNG 不超过 500 KB。
- **从不覆盖**：用 `current` 指针挑选；单张失败不拖累整批。
- **打包**：附 `manifest.json` 和 `checksums.sha256`；只带挑中的图。

**为什么**：这两条产线真正不同的只有三件事：出什么清单、提示词里的固定约束、产物怎么裁怎么摆。把这三件事收进模板，引擎只写一份。
详见 [DESIGN.md §40](../../DESIGN.md#40-图片集引擎与表情与头像纪念写真2026-09-09)。

### 2.7 图片工作台

- 它是图片集引擎的第三个模块，有三个模板：
  - 自由出图：一句话出一张或几张。
  - 多模型对比：同一句提示词，每个模型出一张，差别只来自模型。
  - 图卡：给图片叠标题，复用海报的叠字。
- 主体可以完全留空，只写画面。
- 多模型对比的候选模型来自这台电脑：已配置的模型 → 模型目录缓存 → 本机扫描结果。只读缓存，不为列候选发任何请求；都没有时退回模板自带的默认列表。

**为什么**：共享引擎，就自动继承了挑选、从不覆盖、后处理、打包、后台任务这些能力，不用再写一套。
详见 [DESIGN.md §42](../../DESIGN.md#42-图片工作台2026-09-10)。

### 2.8 配乐

- **产品是一次投放，而不是一个音频文件**：按意图出几条候选 → 试听挑一条 → 一键放进短剧的配乐层、绘本的背景音乐，或者播客的片头、垫乐、片尾。
- **意图要说清楚**：简报包括用途、情绪、体裁、乐器、速度、结构、要避免的；有 10 张预设简报可以直接套用。
  只填了时长、没说要什么音乐的简报不让提交，免得花钱换一段谁都能写的「废话」音乐。
- **逐条提交**：一条失败不拖累其余；从不覆盖。
- **投放是拷贝**：音频拷进目标项目的素材目录（文件名带内容摘要，重复投放不会堆出副本），写回时走目标模块的校验。
  短剧那边走后期块，制作中也能投放。
- **没有内置来源**：音乐接口没有通用的形状，要用「生成」需要装一个提供 `music` 角色的插件。各模块上传本地音频做配乐不受影响。

**为什么**：拷贝而不是引用，删掉配乐项目不会让别人的成片突然少一条音轨。
详见 [DESIGN.md §44](../../DESIGN.md#44-配乐模块2026-09-10)。

### 2.9 音色库

- **一条音色档案有两部分**：
  - 声音描述：按性别、年龄段、音色、语速、音量、口音、情绪这些维度拼成中英两版。
  - TTS 参数：引擎（`edge` 免费在线音色 / `settings` 模型设置里的语音模型 / `minimax`）、音色、语速、音调。
- **两种用法**：
  - 绑给角色：描述文字进每一镜的视频提示词。视频模型直接出台词时只能接受文字，同一段描述能让各镜的声音更像同一个人，但不保证完全一样。
  - 绑给旁白或配音：用 TTS 合成，音色真正稳定。
- **绑定是拷贝，不是引用**：改音色库不会悄悄改掉已冻结项目的提示词。要同步就在项目里重新绑一次：绑给角色属于生成字段，开始制作后要开新版本；旁白是后期块，随时能改。
- 试听样本不原地覆盖：参数一变就写新文件名（带参数哈希和时间戳），旧样本随后会被清理，只留最新的一个。
- 可以给档案配参考音频并克隆音色（目前只接了 MiniMax，未用真实账号验证）。

**为什么**：冻结的承诺不能被一个全局文件绕过去。详见 [DESIGN.md §12](../../DESIGN.md#12-音色库2026-09-07)、[§33](../../DESIGN.md#33-音色克隆与参考音频2026-09-08)。

### 2.10 出图风格卡

- 24 张共享卡，分 8 类：人像写真、插画、角色与表情、产品、时尚、美食、海报与平面、界面与社交。
- 每张卡有中英锚句、布光、色板（5–7 个具体色名）、材质、镜头观感、约束，以及「适合哪些模板」。
  「适合」只用来筛选，不做硬限制。
- 镜头观感只写看起来是什么样，不写焦段、光圈这类数字：这类数字换不来对应的画面。
- 用在图片集（表情、写真、图片工作台）、绘本、单条视频和海报。
- 不挑卡、方言选「自动」时，项目文件里不写这些键，提示词不会因为有了风格卡而改变（有意的措辞调整另见原则 8）。
- 卡的文字是本仓库按常见的摄影布光、插画技法和版式常识自己写的，出处写在卡库里。

**为什么**：以前每个模板各写三四条风格预设，散在代码里；收成一套共享卡库，各模块风格一致，也方便增补。
详见 [DESIGN.md §41](../../DESIGN.md#41-出图风格卡与图像方言2026-09-09) 和 [image-style-cards](../image-style-cards.md)。

### 2.11 回收站

- 所有模块的「删除」都进回收站：项目文件、`output/<模块>/<id>/` 里的产物、`content/assets/<id>/` 里上传的素材，一起搬进 `.webui_deleted/<模块>/<id>__<时间>/`，附一份 `manifest.json`。短剧另外带上剧本和账本记录。
- 恢复时按固定布局放回原位，而不是按 manifest 里记的路径，防止一份被改过的 manifest 把文件搬到数据目录之外。
  恢复不覆盖已有文件，要么全部成功，要么什么都不动。
- 文件被占用或者还有任务在跑时，删除会整体拒绝，不会搬到一半。
- 自动编号不会发出回收站里还在的 id；手动填的 id 撞上了，恢复时会返回 409 并说明原因。
- 「彻底删除」只在回收站页面里做。

**为什么**：删除从来不是直接删文件。花钱换来的产物，不该因为一次误点就找不回来。

### 2.12 任务中心

- 等待生成结果、台词识别、后期合成、出图、配音、导出这类长任务都在后台跑：接口立刻返回任务 id，界面轮询进度。
- 任务记录存在 `<数据目录>/.webui_draft_cache/tasks/`，从不删除。
- 同一个项目、同一种任务，同一时间只跑一个。重复点击直接拒绝（409），而不是排队：排队会让人以为第一次没生效，再多点几次。
- 任务中心跨模块列出所有任务：模块、种类（用人话写）、项目、状态、开始时间、用时、失败原因。这一页只读，不会发起任何生成。
- 有任务在跑时每 3 秒刷新一次，全部停下就不再轮询。
- 服务重启后，短剧和单条视频里还没拿到结果的任务会自动接着等（只轮询、下载、记账，不提交、不花钱）。

**为什么**：生成视频动辄几分钟到几十分钟，不能让一个 HTTP 请求一直挂着，也不能因为关了页面就丢掉进度。
详见 [DESIGN.md 任务中心一节](../../DESIGN.md#工作台首页与模块首页分家--任务中心2026-09-10)。

### 2.13 工作台外壳

- 启动台（`/`）依次是：产品名、模块卡、最近改过的项目、「N 个任务在跑」、第一次使用的三步引导（配好模型 → 选一个模块开始 → 花钱前都会先问你）。
  最近项目、在跑的任务、第一次使用引导这几块，没有内容时不显示。
- 侧栏只放导航；「新建」是动作，只放在模块首页。
- 除剧本工作台外，各模块首页都有「复制示例」（不花钱），不配模型也能先看一个完整的项目长什么样。

## 三、技术取舍

- **后端 Python + 本机窗口用 pywebview + 用 PyInstaller 打包**，不选 Electron，暂不换 Tauri。
  pywebview 在 Windows 上用 WebView2，在 macOS 上用 WKWebView。
  界面只通过 HTTP 和后端通信，不依赖 pywebview 的 JS 桥，所以以后需要自动更新时可以换壳（首选 Tauri v2）。
  见 [DESIGN.md §8.1](../../DESIGN.md#81-技术栈决策2026-09-07)。
- **账本用标准库的 SQLite**（WAL 模式，数据库结构有版本号并能自动迁移；更新版本写过的账本，旧版本程序会拒绝打开）。
- **音视频处理都交给 ffmpeg / ffprobe**（装配、后期合成、混音、绘本出片）；海报、图卡、图片集的叠字和后期角标用 Pillow 画。
- **前端是 Vue 3 单页应用**，用 hash 路由；构建产物提交在仓库里，只跑 Python 不需要 Node。
- 版本号只有一个来源：`src/genkit/version.py`。

更多见 [架构](architecture.md)。

## 四、不做什么

- 多人协作与权限、云端渲染队列、素材商城、账号体系、任何厂商独占的功能。
- 实时协作：同一个项目目录同一时间只给一个人操作（生产时有文件锁）。
- 局域网或远程访问：服务只绑本机。
- 不承诺任何厂商的审核策略：被审核拦截时，按「改写提示词或换镜」处理。

见 [DESIGN.md §2](../../DESIGN.md#2-给谁用解决什么)、[§10](../../DESIGN.md#10-非目标与风险)。
