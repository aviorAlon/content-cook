## 费用

### 这个软件收费吗？

不收费。Content Cook 以 [MIT 许可证](../../LICENSE) 开源。
花钱的是你自己接的模型服务：生成请求直接发到你配置的来源，按那家服务的价格计费。
本机模型不花钱，Edge TTS（微软的在线朗读服务）也是免费的。

### 会不会不小心花很多钱？

程序在几处刻意防止多花钱，但它**不知道**各家服务的价格，只能告诉你要发几个请求：

- **先预估、再确认**：发起一批生成之前，会先告诉你这次要发起几次请求。
  短剧的预估带一个「计划指纹」，确认时按磁盘上的最新状态重算；预估之后项目有变化，就拒绝提交、一个请求都不发。
- **程序不自动重试**：AI 起草不会重试，也不会一次生成多个候选；明确失败的任务不会自动重提，要你自己决定重提。
  但各家官方 SDK 自带一层传输重试，程序目前没有关掉：`openai_chat` / `openai_images` / `openai_speech`
  （OpenAI SDK，`max_retries=1`）遇到超时、网络错误、429 或 5xx 会再发一次；火山方舟来源按 SDK 默认最多再发两次；
  OpenRouter 来源按 SDK 默认在 5xx 和网络错误时退避重试。极少数情况下一次提交可能被服务商收到两次，请以服务商控制台为准。
- **不重复提交**：短剧每次付费提交前先在账本里记下「正在提交」，程序中途崩溃后不会再提交一次；
  拿不准远端有没有收到请求时，任务会停下来等你处理，而不是再发一次。
  （这防的是程序崩溃；上面说的 SDK 在一次提交内部的重试不在此列。）
- **原样重拍有上限**：同一镜同一份提示词已经出过 2 次，第 3 次原样重拍会被拦下，建议改文字、换模型或接受当前结果（界面上确认后可以强制）。
- **本机来源**：配成本机服务的角色，费用提示会改成「本地生成，不花钱（N 次请求）」。

具体的价格请看你所用服务的控制台。

## 隐私与数据

### 我的数据会发到哪里？

- 服务只绑定 `127.0.0.1`，每次启动生成一个随机访问令牌，并校验 Host 和 Origin，防止别的网页借浏览器操作本机服务。
- 生成时发出去的是提示词、参考图 / 参考音频和参数，收件方是**你配置的**模型来源。
- 音色克隆会把你上传的参考录音发给 MiniMax。
- 旁白、朗读、播客配音没有指定音色、也没配别的语音来源时，默认用 Edge TTS，要念的文字会发给微软的服务。
- 启动时，上次退出时还在服务商那边的首帧 / 视频任务会自动接着轮询和下载（只查询、不新提交），收件方是当初接单的那个来源。
- 下面这些只在你操作时才联网：刷新 OpenRouter 公开模型目录、测试统一网关（成功后顺带拉网关的 `/models`）、
  检查更新（填了更新地址才有）、打开「音色库」页面（拉 Edge TTS 音色列表）、一键安装台词识别组件（从 PyPI 下载）、
  在设置页下载或第一次使用台词识别模型（从 Hugging Face）。
- 没有遥测，不收集使用数据。

### 密钥存在哪里？安全吗？

密钥只存在本机的 `~/.storystudio/settings.json` 里。它是**明文**保存的，程序在每次保存后把文件权限收紧到只有当前用户能读写。
接口返回给界面的密钥一律打码，日志和任务记录也会遮掉密钥。
换来源、或者把地址改到另一台主机时，旧密钥会自动清掉，不会被发到别处。细节见 [配置参考 §2.4](configuration.md#24-密钥怎么处理)。

### 能从手机或另一台电脑访问吗？

不支持。服务只监听本机，并且拒绝 Host 不是本机的请求。这是有意的设计，不建议用反向代理或端口转发绕过它。

## 模型

### 应该用哪些模型？

程序没有推荐清单，也没有做过模型之间的评测。

- 文本角色可以接任何 OpenAI 兼容的对话接口（云端或本机）。
- 生图、语音、视频各有几种内置来源，每种来源在表单里有默认模型，那只是起点，不是推荐。
- 程序对已知的模型有一张参数能力表，开始制作前会检查画幅、时长等参数是否越界；表里没有的模型也能用，只是越界要到提交时才会报错。
- 不同模型的提示词写法（「方言」）会按模型自动选择，但这些写法还没拿真实模型对比过。

完整的来源列表见 [配置参考 §3](configuration.md#3-模型角色与内置来源)。

### 这些来源都测过吗？

没有全部测过。写这份文档时（v0.1.0）：

- 用真实文本模型（经 OpenAI 兼容接口）加 Edge TTS 走通过播客从起草到导出的整条流程；
- Edge TTS 真实合成过；
- 其余多数直连来源（OpenRouter、火山方舟、MiniMax、OpenAI 的图片 / 语音 / 视频接口）只用假客户端测试过，还没用真实账号联调；
- 完整长度的短剧出片与后期合成、音色克隆、本机模型在真实硬件上的表现都还没验证。

逐项状态见 [CHANGELOG.md](../../CHANGELOG.md) 的「已验证 / 未验证」和 [BACKLOG.md](../../BACKLOG.md) 的「现状盘点」。
如果你用真实账号跑通或跑出问题，欢迎[提 issue](#怎么报告问题) 告诉我们。

### 能完全离线用吗？

理论上可以，但没有在真实硬件上验证过。需要同时满足：

- 每个要用的角色都配成本机服务（比如 Ollama 做文本、ComfyUI 做生图和视频、本机 OpenAI 兼容语音服务做配音）；
- 旁白和配音不用 Edge TTS（它是在线服务）；
- 如果要用台词识别闸，faster-whisper 和模型要在联网时先装好、下载好。

### 为什么「配乐」模块点不了生成？

配乐这一档没有内置来源：音乐生成没有通用的接口形状，需要装一个提供 `music` 角色的插件。
在短剧、播客、绘本里上传自己的音频做配乐不受影响。

### 需要显卡吗？

用云端来源不需要。台词识别（faster-whisper）在 CPU 上运行。只有想在本机跑生成模型时才需要合适的显卡。

## 文件与项目

### 我的文件在哪？

| 内容 | 位置 |
|---|---|
| 项目、生成的图片 / 视频 / 音频、短剧账本、回收站 | **数据目录**：桌面版默认 `~/StoryStudio`；从源码运行 `storystudio` 默认是启动时的当前目录，命令行 `storyvideo` 默认是仓库根；可用 `--project-root` 或 `STORYSTUDIO_PROJECT_ROOT` 指定 |
| 模型设置与密钥、日志、缓存、音色库、插件 | `~/.storystudio`（可用 `STORYSTUDIO_HOME` 指定） |
| 日志 | `~/.storystudio/logs/storystudio.log` |

完整的目录结构见 [配置参考 §9、§10](configuration.md#9-数据目录结构)。

注意：「镜头库与风格库」页面的修改写进程序自带的数据文件，而不是数据目录。
源码安装会改动仓库里的文件；打包版的这条路径没有测过（装在 Program Files 下时很可能保存失败，写进去了重装也会覆盖）。

### 为什么项目「锁住」了，有些内容不能直接改？

短剧项目点了「开始制作」之后，项目会被**冻结**：之后每一笔生成都记进账本，保证不会因为改了项目而把已经花钱生成的结果和新的请求混在一起。

- 旁白、插卡、画面文字、字幕这类**后期内容**随时能改，不需要开新版本（命令行对应 `storyvideo amend`）。
- 改角色、镜头画面、台词这类**会进提示词**的内容时，界面会先预告哪些镜要重新生成，确认后**保存为新版本**，能复用的产物会带过去。
- 平台临时出错导致失败的任务，可以原地重提（`storyvideo retry-failed`），不需要新版本。

用命令行直接改了已冻结的项目时，会看到 `episode source changed after the run was frozen; create an explicit revision`
这样的报错，做法同上：开新版本。细节见 [STORYVIDEO_RUNTIME.md](../../STORYVIDEO_RUNTIME.md) §5。

### 任务提示「提交后没拿到结果，不确定服务商是否收到」怎么办？

这表示请求发出去了，但程序没拿到远端的任务 id（比如提交途中网络断了）。为了不重复扣费，程序不会自动再提交。
目前内置来源都不支持查询任务历史，所以这种任务没法在原项目里直接解开（已知问题）。
做法：先到服务商的控制台确认这次请求有没有真的提交，再开一个新版本，卡住的那一镜在新版本里是一个新任务。
见 [STORYVIDEO_RUNTIME.md](../../STORYVIDEO_RUNTIME.md) §6。

### 删掉的项目能找回吗？

能。删除会把项目文件、产物和上传的素材一起移进回收站（数据目录下的 `.webui_deleted/`），在「回收站」页面可以恢复或彻底删除。

## 升级

### 升级后为什么提示词变了，项目要求开新版本？

新版本有时会调整发给模型的提示词措辞。提示词一变，请求的「指纹」就变了：

- 已冻结的短剧项目会拒绝按新提示词继续提交（`already has different inputs`），要开一个新版本；
- 单条视频项目会被标成「提示词已改」（`stale`），再出片时按新请求提交；
- 绘本、海报这类出图时现编提示词的，再出图就按新提示词提交；图片集、纪念写真这类在「展开清单」时把提示词写进项目文件的，
  已展开的清单保留旧文字，重新展开后才用新文字。

这类改动按惯例会写在 [CHANGELOG.md](../../CHANGELOG.md) 里（v0.1.0 见「提示词措辞调整」一节），说明影响哪些项目。

### 升级会动我的数据吗？

不会。桌面版用新安装包覆盖安装即可（安装包用固定的应用 id，按设计会原地升级；安装包本身还没有实际跑过，见[平台支持](#平台支持)），
`~/StoryStudio` 和 `~/.storystudio` 不受影响。从源码安装的，拉取新代码后重新执行 `pip install -e ".[desktop]"`。
新版本第一次以可写方式打开短剧账本时（界面服务启动时就会打开一次）会自动升级格式；升级后的账本旧版本打不开。
设置里选了新版本不认识的来源时，设置原样保留。

## 插件

### 插件是什么？安全吗？

插件用来接入内置来源之外的模型服务，放在 `~/.storystudio/plugins/<名字>/`，启动时自动加载，核心代码不用改。

插件是普通的 Python 代码，**以你的用户权限运行**，可以做你本人能做的任何事。只装你信任、看过代码的插件。
插件接口 v1 是实验性的，1.0 之前可能调整。

临时不加载插件：启动时加 `--no-plugins`，或设环境变量 `STORYSTUDIO_PLUGINS=off`。
插件加载失败时程序照常启动，设置页会说明原因。写法见 [插件文档](../plugins.md)。

## 平台支持

### 支持哪些系统？

写这份文档时（v0.1.0）的实际情况：

| 系统 | 状态 |
|---|---|
| Windows x64 | 打包版（PyInstaller 单文件夹）开发时构建并运行过；安装包（Inno Setup）只在 CI 配置里构建，还没有实际跑过；程序未签名 |
| Linux | 按设计可以从源码运行（字体查找等有 Linux 分支），CI 配置了在 Ubuntu 上跑后端测试（写这份文档时 CI 还没在 GitHub 上跑过），但没有手动验证过整套使用流程。没有安装包；原生窗口（pywebview）没测过，建议用 `storystudio --browser` |
| macOS | 打包脚本 `desktop/build_macos.sh` 已写好，但**从没在 Mac 上运行过**；从源码运行也没验证过 |

Python 要求 3.10 及以上，但只在 3.11 上测试过。

### 为什么命令叫 storystudio，不叫 content-cook？

「Content Cook」是产品名（目前是工作名），在 `src/webui/branding.py` 定义，界面、窗口标题都从那里读
（Windows 安装脚本 `desktop/installer.iss` 里另有一份同样的默认名，由测试保证两边一致）。
Python 包名、命令行（`storystudio`、`storyvideo`）、设置目录（`~/.storystudio`）、桌面程序（`StoryStudio.exe`）
是技术标识，不是产品名，刻意不跟着产品名改。

## 运行问题

### 启动时报端口被占用

不带 `--port` 时，启动器从 8756 开始依次找空闲端口（到 8799 为止）。
用 `--port` 指定了一个被占用的端口时，启动器会打印占用它的程序（能查到时）和一个可用端口，然后以退出码 2 退出，换个端口就行。

### 界面顶部提示缺少 ffmpeg

拼接视频、后期合成、绘本和播客的渲染、台词识别都要用 `ffmpeg` 和 `ffprobe`。
把它们装到系统 PATH 里（下载见 <https://ffmpeg.org/download.html>）。
桌面版也可以把 `ffmpeg.exe`、`ffprobe.exe` 放进程序目录或它下面的 `ffmpeg/` 子目录。

### 字幕、插卡上的中文显示不出来

烧进画面的字幕和文字需要中文字体。程序会按系统找常见字体（Windows 的微软雅黑 / 黑体 / 宋体，macOS 的苹方等，
Linux 的 Noto Sans CJK / 文泉驿等），找不到时健康检查和后期面板会提示。Linux 上可以装 `fonts-noto-cjk`。

### 用 curl 调接口返回 401

默认启用了本机访问令牌。带上请求头 `X-StoryStudio-Token: <令牌>`（令牌在启动器打印的地址里），
或者调试时用 `storystudio --no-token` 启动。不要在日常使用时关掉令牌。

### 原生窗口打不开或显示异常

改用系统浏览器：`storystudio --browser`。没装 pywebview 时启动器也会自动退回浏览器。
报错信息看日志 `~/.storystudio/logs/storystudio.log`。

## 反馈与参与

### 怎么报告问题？

在 GitHub 上[新建 issue](https://github.com/aviorAlon/content-cook/issues/new/choose)，选「问题报告」模板，写上：

- 版本（`storystudio --version`，或设置页上显示的版本号）、安装方式（源码 / 桌面版）、操作系统、Python 版本；
- 用的是哪个角色、哪个来源（来源 id 即可，**不要贴密钥**）；
- 复现步骤、期望结果、实际结果；
- 日志里相关的几行（日志里的路径带用户名，贴之前替换掉，也检查一遍有没有别的不想公开的内容）。

**安全问题不要开公开 issue**，按 [SECURITY.md](../../SECURITY.md) 私下报告。

### 想参与开发

见 [参与贡献](../../CONTRIBUTING.zh-CN.md)。参与之前请先读 [行为准则](../../CODE_OF_CONDUCT.md)。
