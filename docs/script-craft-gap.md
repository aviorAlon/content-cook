# 剧本工艺清单：判据对照与落地记录

status: 2026-09-16。把剧本与分镜常见的质控判据逐条对照本仓库已有的检查，决定哪些做成静态检查、哪些交给模型审稿、哪些不做。整理出来的这一套叫「剧本工艺清单」（script craft checklist）：能数的进 lint，数不了的进 `skills/ai-short-film/scripts/craft_checklist.json`，走带引文核验的模型审稿。

融合原则跟 [drama-skills-gap.md](drama-skills-gap.md) 一样：**取判据，不取语法**——不引入正文标记、表格约定或打分，同一件事做成 spec 字段 + 静态检查 + 带引文核验的模型审稿。落地的优先级：能自动注入的先注入，其次做检查告警，最后才写成文档规范。

## 出处（先说）

清单只取判据：不引入任何外部的标记语法，条目用本仓库自己的措辞写，每条的 `basis` 写明依据与置信度。跨集兑现是本仓库早就有的 `episode_contract.must_pay_off` + `series` 记忆（DESIGN §32）；伏笔回收只取判据、不加标记。

## 逐条对照

按本仓库的层次排：分镜层 → 剧本层与单集契约 → 语义判据 → 合规与交付。

| 判据 | 能否机械化 | 我们已有 | 处理 |
|---|---|---|---|
| 台词装不装得下（按字数估的发声时长） | 可 | `preview.shot_duration_budget`：4.5 字/秒（慢端 3.5）+ 扣开口等待与末尾反应窗口 | 已覆盖，不改 |
| 单镜过长要拆段 | 可 | `check_form`（有形态时）+ 视频模型参数范围（提交时） | 不改；记一条：没选形态时缺通用上限提示（待做，低） |
| 运镜没写 / 相邻镜运镜相同 / 一镜多种主运镜 | 可 | `camera_move` 枚举有 profile 默认；相邻同功能同景别 `check_purpose` | 相邻同运镜**不采纳**——连着用同一种运镜常常是有意的，得由人判断、不能机械改，做成告警只会是噪音；**一镜多种主运镜**（推 + 环绕写在同一镜正文里）→ 新增 `lint.check_camera_motion_single` |
| 画中带字的东西（招牌 / 屏幕界面 / 纸面文件等）要声明怎么处理；字幕不算 | 可 | 文字政策 `readable_text` 只管**声明了**的文字（DESIGN §20） | 新增 `lint.check_text_carriers`：正文提到文字载体、本镜既没声明 `readable_text` 也没写「无文字」→ 告警「模型会自己编字」 |
| 情绪要落到看得见的地方：抽象情绪词、写给人看的制作备注混进提示词 | 可 | 抽象词 ≈ `INFERENCE_WORDS`（可生成性）+ `EMOTION_WORDS`（表演）；正文卫生管镜号 / 文件名 / 版本号 / 同上 | **写给人看的制作备注**（生产说明）并入 `check_prompt_hygiene`；五种关系场景（表白 / 重逢 / 原谅 / 拒绝 / 分手）各有该看见的动作，但要先有场景类型字段——记入待做（中） |
| 一句重话之后要看到听的人的反应（愣住 / 手上一停 / 别开脸 / 退一步） | 半可（要 purpose） | `shot.purpose` 有 `impact / shift / reaction / aftermath` | 新增 `lint.check_reaction_after_impact`：只在前后两镜都写了 purpose 时判，冲击 / 转折镜之后不是反应 / 余波 → 提示 |
| 旁白与对白撞车：同一时段两条人声、旁白超出本镜、旁白指到不存在的镜 | 可 | `voice_over.lines[{shot, at, zh}]` + 镜内 `lines`，装配时按绝对时间 adelay，但**没有人查重叠** | 新增 `lint.check_voice_over`：同一镜旁白时段（at + 字数 ÷ 4.5）与对白窗口（开口等待后 + 纯语音）相交、旁白超出本镜、旁白指到不存在的镜 |
| 台词单句 >25 字、一集开口的人 >3 | 可 | 分镜层由时长预算兜住；剧本层没有；`MAX_SCENES = 12` 软提醒 | 新增 `screenplay.check_line_length`（一句 >25 字提示拆句或改成动作）与 `screenplay.check_speaking_cast`（开口的人 >3 软提示：观众记不住脸，模型也容易认混） |
| 承诺要兑现，作者可以明说本集不兑现（有意留白） | 可 | `episode_contract.must_pay_off` + `contract.payoff_status`（正文里提到了吗）+ `series` 记忆的「已兑现 / 未决」 | 不引入标记；判据已覆盖。差一个「有意留白」的显式豁免（待做，低） |
| 数不了的语义判据：张力（有没有人在争、翻盘有没有迹可循、集末停没停在答案之前）、情绪（有没有落到身体上、话里有没有留一层）、节奏（新信息来得勤不勤、有没有松紧） | 语义判断，词表判不了 | 按题材审稿（DESIGN §49）已经有「模型判 + 程序核对引文」的闸门 | 待做（高）：**剧本工艺审稿**——把这些做成一张不分题材的工艺清单，复用 `genre_review.verify_review` 的核对，问题卡分类「工艺」；合规红线作为其中一组 |
| 合规红线（按类别列的敏感内容）一票否决；交付时说明哪些内容由 AI 生成、各环节用了哪个来源 / 模型，并提示备案 | 正则可跑但误报高（敏感词在正当剧情里也会命中） | 起草提示词里有一条 IP 合规自检；导出交付包有 manifest，但没写哪些是 AI 生成、用了什么来源 | **红线不做正则**，做成模型审稿的一个维度（引文核验，跟按题材审稿同一闸门）；**AI 生成声明与来源记录**做进交付包 `manifest.ai_disclosure`——账本知道每镜用了哪个来源 / 模型，自动生成，不靠人填 |

## 已融合（2026-09-16）

| 判据 | 我们的落地 | 位置 |
|---|---|---|

## 待做（按价值 / 工作量排）

1. 剧本工艺审稿的真模型效果：条目比题材卡长得多，模型会不会老实按条目写的条件判、通读全集才能判的条目会不会编引文、合规组会不会过度报 risk、16 条的漏答率——要拿 key 对几集真稿跑过。
2. 用真实项目跑一遍 `check_relation_boundaries` 看误报率再调词表（中英两套都是自拟经验词，没有语料可校准）；拒绝点定序是按字符位置的粗定位，强拒绝词或挡开动作写的是别的意思（「离开」「转身」说的是第三人）时会把前面的强行接触压掉。
3. 账本每个 job 只记最近一次提交的来源；要逐次历史得另加一张表。

## 不照搬的

- 关键词计分：说不清来源，也会被凑词绕过；我们只报能落到某一镜 / 某一场的具体问题。
- 相邻镜运镜相同的告警：连着用同一种运镜常常是有意的，对话戏刻意固定机位更是常态，做成告警只会被忽略。
- 合规红线正则：正当剧情里的敏感词也会命中，一票否决交给正则不负责任；改由模型审并核验引文，最终判断留给人。
- 拒绝场的「拒绝之后」只做字符位置的粗定位（2026-09-17）：先在正文里找第一次出现拒绝表态或挡开动作的位置——强拒绝词（别碰我 / 放开 / 松手 / let go / don't touch me…）任何位置都算，弱词（不要 / 不行 / 我不 / no / sorry…）在别的句子里太常见（「不能挣脱」「我不知道」「no sound」），只在台词里直接算、动作正文里要写成开口的话（说话动词或引号 + 弱词 + 句读 / 句尾）才算，各段之间用换行拼接让句尾成立，跟强行接触词有重叠的候选不算（"won't let go" 里的 let go）；有拒绝点时只报它之后的强行接触，没有就同镜出现即报。这样弱词最多把拒绝点提前（多报），不会凭空造出靠后的拒绝点压掉前面的接触；不是语义顺序，正文是「台词 → 动作 → 美术」拼的，美术不参与定位。
